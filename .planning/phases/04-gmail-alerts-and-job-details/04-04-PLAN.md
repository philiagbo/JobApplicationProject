<objective>
Collect one real job-alert email per site, safe to commit. The person exports four alert emails from Gmail into a gitignored folder. The executor turns each into a small readable `.eml` (original From, Subject and Date, one decoded UTF-8 body, no delivery headers), removes the person's address and name taken from the recipient headers, and prints a report of what still looks personal. The person then finishes the redaction by hand and confirms.

Purpose: D-06 requires each parser to be tested against a real alert, and D-07 requires the samples to be hand-redacted and committed under `api/samples/` so the tests run anywhere. Gmail exports are usually quoted-printable or base64, which cannot be redacted by hand in that form, so the decode step makes the hand redaction possible. Scheduled in wave 3, after the Gmail infrastructure (04-02), so this human step never blocks the automated build; the parsers in 04-05 follow straight after.
This plan carries no feature code, so it has no tracer (same shape as 04-01). The parser tracer lives in 04-05.
Output: the four samples under `api/samples/`.

Commit note: the user approves every commit (user memory). The commit of the samples is the last check that nothing personal remains: show `git diff --cached --stat` and the report, and wait for approval.
</objective>

For each site in linkedin, indeed, cv-library, totaljobs:
- Parse api/data/alert-samples/{site}.eml with email.message_from_bytes(raw, policy=email.policy.default).
- Collect the recipient's identity: every address in the To, Cc, Delivered-To and X-Original-To headers (email.utils.getaddresses), and every word of three or more letters in the To and Cc display names.
- body = alerts.email_body(msg); the subtype is html when the message has an HTML part, otherwise plain. Stop and report the site when the body is empty.
- Scrub mechanically: replace each collected address, case-insensitively, with person@example.com, and each display-name word, as a whole word and case-insensitively, with Person, in both the body and the Subject.
- Write api/samples/{site}.eml as UTF-8 text with "\n" line endings: the original From and Date headers, the scrubbed Subject, MIME-Version: 1.0, Content-Type: text/{subtype}; charset="utf-8", Content-Transfer-Encoding: 8bit, a blank line, then the scrubbed body. No other headers: To, Cc, Delivered-To, Received, Return-Path, DKIM, ARC and list headers are all dropped.
- Append the collected addresses and words (lowercased, one per line, no duplicates) to api/data/alert-samples/scrub-terms.txt. This file stays in the gitignored folder and is what the checks below compare against.

Then print a report for the person, per site: the From address; the scrubbed Subject; the body subtype and length; the number of anchors; the ten most common link host plus first path segment pairs (so 04-05 can see whether job links are direct or go through a click-tracker host, RESEARCH A2); and, with line numbers in api/samples/{site}.eml, every remaining email address, every query value of 24 or more characters, and every line containing unsubscribe, manage, account, preferences or settings. Print only the line number and the first 120 characters of each such line.

Commit nothing in this task: the person redacts by hand in Task 3 first (D-07).
