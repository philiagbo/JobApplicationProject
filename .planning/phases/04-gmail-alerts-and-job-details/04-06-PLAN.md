<objective>
Add the single Playwright browser thread and use it for the one retry DETAIL-02 asks for. When urllib cannot read a job page (blocked status, a challenge, too little text, or a JavaScript-rendered page), the details worker hands the page to the browser thread once. The thread opens the installed Edge or Chrome headless, loads the page, reads it and closes it. If it is still unreadable the job is marked `blocked` ("open listing to read"). Nothing on a page is ever clicked or typed into, and no CAPTCHA is ever touched.

- _start_playwright() returns sync_playwright().start(). Tests replace it.
- _run(q): pw = _start_playwright() inside try/except Exception (log the failure; keep the error). Then loop forever: fn, fut = q.get(); skip when fut.set_running_or_notify_cancel() is false; when Playwright failed to start, set BrowserUnavailable("Playwright could not start: " + the error text) on the Future; otherwise set fn(pw) as the result, catching BaseException into fut.set_exception so one task can never kill the thread. The queue is passed in, so the thread keeps the queue it started with.
- submit(fn): under _lock, when _thread is None or not alive, start threading.Thread(target=_run, args=(_q,), name="browser", daemon=True). Create a Future, put (fn, future) on _q and return the future. Only the details worker calls it in this phase; Phase 5 adds its own task functions on the same queue.
- launch_headless(pw): when _unavailable is set, raise BrowserUnavailable(_unavailable) at once. For each channel in CHANNELS, return pw.chromium.launch(channel=channel, headless=True), and on Error try the next. When both fail, set _unavailable to "Edge or Chrome is not installed" and raise BrowserUnavailable with it (D-15). Never surface, log or follow Playwright's install hint, and never download a browser. ponytail comment: the result is remembered for the process, so installing Edge or Chrome needs an app restart. Pass only channel and headless: no user-agent override and no extra launch arguments; headless Chrome announces itself, and more blocked pages are the designed outcome (RESEARCH Pattern 7, A9).
- _load_page(pw, url) -> (status, html): browser = launch_headless(pw); inside try/finally that closes the browser: page = browser.new_page() with no options; inside try/finally that closes the page: response = page.goto(url, wait_until="domcontentloaded", timeout=GOTO_TIMEOUT_MS); then page.wait_for_load_state("networkidle", timeout=IDLE_TIMEOUT_MS) inside try/except Error (best effort for script-rendered pages); when core.http_url(page.url) is false return (0, ""); otherwise return (response.status if response is not None else 0, page.content()). The task only navigates, waits, reads and closes: no input, event or script APIs on the page, and no waiting for a challenge to clear (D-16).
- fetch_page(url) returns submit(lambda pw: _load_page(pw, url)).result(timeout=RESULT_TIMEOUT_SECONDS).
