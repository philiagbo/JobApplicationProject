<objective>
Ship saved answers end to end. The person saves answers through `/api/answers` (list, create, edit, delete). Company-specific and over-300-character answers are refused with a clear reason. `find_answer` matches a form label to a saved answer, exactly or fuzzily (0.85 or above), and maps it onto dropdown or radio options. That is the input Phase 5 autofill will fill from. The common application questions are seeded on startup so the person has a list to fill in.

Purpose: covers PROF-02, PROF-03, PROF-04 and decisions D-05, D-10 to D-14. This plan leads the phase with the tracer slice (Task 1). It needs no new packages, so it runs in wave 1 alongside the dependency gate in 03-01.
Output: pure matching and blocking functions in `api/core.py`, answer helpers in `api/db.py`, four routes in `api/app.py`, and tests in `api/test_core.py` and `api/test_api.py`.
</objective>

api/core.py (pure, no DB):
- Import difflib. Add constants FUZZY_MIN = 0.85, MAX_ANSWER_CHARS = 300 and MAX_QUESTION_CHARS = 500. Add a module-level set _LEGAL of legal suffixes: ltd, limited, plc, inc, llc, llp, corp, corporation, co, uk.
- answer_block_reason(question, answer, company="") per D-12 and RESEARCH.md Pattern 6. If len((answer or "").strip()) is greater than MAX_ANSWER_CHARS, return "longer than 300 characters" (build the number from the constant). Otherwise take the words of normalise(company or ""), drop the words in _LEGAL, and fall back to all the words when every word is a suffix. Join the result into name. When len(name) is at least 2, return "mentions the company" if " name " (space-padded) occurs inside the space-padded normalise(question) or normalise(answer). Otherwise return None. This is whole-word matching, the same technique score uses for excluded words, so a company "BT" never blocks "debt".
- _ratio(a, b) returns difflib.SequenceMatcher(None, a, b, autojunk=False).ratio(). autojunk=False matters because the default junk heuristic distorts ratios on strings of 200 characters or more.
- _polarity(norm_text) returns the first word when it is "yes" or "no", otherwise None.
- map_option(answer, options) per D-11 and Pattern 5. Pair each option with its normalise() form. Step 1: return the first option whose normalised form equals normalise(answer). Step 2: when the answer has a polarity, collect the options with the same polarity, and return that option only when exactly one matches. Step 3: return the option with the highest _ratio against the normalised answer, only if that ratio is at least FUZZY_MIN. Otherwise return None. Never pick a first or default option as a guess.
- find_answer(label, answers, options=None) per D-10 and Pattern 5. Set q = normalise(label) truncated to MAX_QUESTION_CHARS, and return None when q is empty. Keep only the answers whose answer text is non-empty after strip (empty seeded answers never match, D-05). Exact: among the rows whose question equals q, pick the max by (updated_at, id) with ratio 1.0. Fuzzy, only when there is no exact hit: loop over the rows with one SequenceMatcher(None, q, row question, autojunk=False) each. Skip a row when real_quick_ratio() or quick_ratio() is below FUZZY_MIN; both are upper bounds, so the skip never drops a real hit. Keep the row with the greatest (ratio, updated_at, id) among ratios at FUZZY_MIN or above. Write this as a plain loop, not the stdlib close-matches helper, which breaks ties by string order instead of recency. No hit: return None. When options is non-empty, run map_option on the hit's answer, and return None when it maps to nothing (never a guess; assumption A4). Return {"id", "question", "answer", "ratio": round(ratio, 3), "option": the mapped option or None}.

api/db.py:
- check_answer_body(body, partial) raises ValueError with the exact API text. A non-dict gives "Answer must be a JSON object". A key outside question, answer, field_type and company gives "Unknown answer field: <key>". A non-str value gives "<key> must be text". When partial is False, a missing question key gives "question is required" and a missing answer key gives "answer is required". Return the dict unchanged.

Empty q raises ValueError("question is required"). len(q) greater than core.MAX_QUESTION_CHARS raises ValueError("question is longer than 500 characters"). The upsert keeps the existing source. Re-select the row by question and return (dict(row), not existed). Use parameterised SQL only.
- list_answers(conn) returns [dict(r) for r in SELECT * FROM answers ORDER BY id].
- find_answer(conn, label, options=None) returns core.find_answer(label, list_answers(conn), options).
