# Phase 04.1 Plan 02: Partial-info flag, con and neutral skills credit Summary

A job whose description is under 500 plain-text characters and was not filled from Reed or pasted is now "partial": `summary.partial_info` is true on every API read, it carries the verbatim con "Only the alert snippet — paste the description for a full score", and (when the profile has a skill) its skills rule gets at least 5 points.

## What was built

- **api/core.py**: `PARTIAL_CON`, `is_partial(job)` (reed/pasted checked first, then `plain_text` length < `SHORT_DESCRIPTION_CHARS`, any source). In `score`, `partial` is computed once; the skills block is `pts = min(2*hits, cap)`, raised to `SKILL_POINTS_CAP // 2` when partial and the profile has a skill; `PARTIAL_CON` is appended last to cons. "Salary not listed" is unchanged and costs nothing.
- **api/db.py**: one line in `job_dict`: `d["summary"]["partial_info"] = core.is_partial(d)`. `core.summarize` is untouched, so stored summaries never hold the key.
- **Tests**: test_core 79 -> 81 (`test_is_partial_rules`, `test_partial_skills_credit`; six exact-cons tests and `test_score_no_skills_no_effect` updated); test_api 60 -> 61 (`test_partial_info_end_to_end`; `SUMMARY_KEYS` gains `partial_info`; `test_profile_change_rescores_new_only` uses 500+ char descriptions); test_details stays 51.
