# Phase 04.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope note (read first)

04.1-CONTEXT.md (Phase Boundary and D-08) puts the UI paste box and the "partial info" badge **out of this phase**: this phase ships the API only, and the UI pages phase (v2, UI-01) builds the screens. The roadmap text still mentions a "paste box", but CONTEXT.md is the later, locked decision.

So this contract has two parts, and keeps both small:

1. **Binding for this phase (API-facing UI contract):** the exact user-facing strings, the data fields the future UI reads, and the error wording. The planner and executor must implement these as written. No `.tsx` or CSS changes are in scope for 04.1.
2. **Forward contract for the UI pages phase:** how the paste box and badge must look and behave when built, so that phase does not re-decide it.

Nothing here invents a design system. `ui/src/index.css` has five tokens (`--bg`, `--text`, `--muted`, `--ok`, `--bad`) and `App.tsx` is a health-check stub; the full token set belongs to the UI pages phase, and this spec only reserves what 04.1 needs.

## Color

Reuses the existing tokens. No new color is introduced by this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` (#fff light, #16171d dark) | Page background, textarea background |
| Secondary (30%) | `var(--text)` / `var(--muted)` on a 1px `var(--muted)` border | Job cards, paste panel surface, badge text and border |
| Accent (10%) | `var(--ok)` (#1a7f4b light, #4ade80 dark) | Reserved: "Description saved" confirmation text only |
| Destructive | `var(--bad)` (#b3261e light, #f87171 dark) | Paste error text only (validation and server errors) |

Accent reserved for: the "Description saved" confirmation after a successful paste. Nothing else in this phase uses accent.

The partial-info badge is deliberately neutral (`var(--muted)` text on a `var(--muted)` 1px outline, transparent fill). It describes missing data, not an error and not a success; using `--bad` would imply the job is broken and `--ok` would imply it is good. Contrast of `--muted` on `--bg` must stay at or above 4.5:1 in both themes; #6b6375 on #fff and #9ca3af on #16171d meet this.

## Interaction Contract (future UI, binding on the UI pages phase)

These behaviours are the minimum so the paste feature feels consistent. The UI pages phase may refine layout but not these rules.

0. **Visual hierarchy (job card and list row):** the score is the primary focal point (Display 28px/600, first thing read). The job title (Heading 20px/600) is next. The `Partial info` badge (Label 14px/600, muted outline) and the `Paste description` toggle (Body 16px, text button) are secondary and must never be larger or higher-contrast than the score. The paste control sits below the pros/cons, not beside the score.
1. **Where it appears:** the badge shows on every job card and list row where `summary.partial_info` is true. The paste control shows in the job detail view and on the card/row expanded state for every job, not only partial ones (a person may want to replace a Reed or scraped description; D-06 says paste always wins).
2. **Paste control states:**
   - Collapsed: a text button `Paste description`.
   - Expanded: labelled textarea (min height 160px, resize vertical), `Save description` button (primary), `Discard description` text button (closes the panel and clears the unsaved text).
   - Saving: `Save description` is disabled and its text stays the same; the textarea is read-only. No spinner needed (local call).
   - Success: panel collapses, `Description saved. This job has been re-scored.` shown in `var(--ok)` for the lifetime of the view, the badge disappears, the score and pros/cons refresh from the response.
   - Error: message in `var(--bad)` directly under the textarea; the textarea keeps the person's text (never clear it on failure).
3. **Disabled rule:** `Save description` is disabled while the textarea is empty or whitespace-only (mirrors the 400 `Paste the job description first`).
4. **Re-score and reorder:** after a paste the job's score changes even if it is queued or dismissed (D-07). In the swipe or list view, a `new` job may move to a new rank; the UI updates its position without a full reload and does not change the job's status.
5. **Accessibility:** the textarea has a visible `<label>`; error text is linked with `aria-describedby` and announced with `role="alert"`; the badge is real text (not color alone) and exposes the tooltip copy via the `title` attribute; the toggle is a `<button>` with `aria-expanded`.
6. **Plain text only:** the textarea accepts any text; the backend stores plain text (D-08, T-04-12). The UI renders descriptions as text, never as HTML.

## UI Considerations

Resolved by the UI-consideration probe after checker approval: 28 applicable — 11 resolved (explicit), 4 resolved (backstop), 13 dismissed with reason, 0 unresolved; plus 2 extra explicit truths (E3 partial filled, E4 re-score) added for completeness. Elements: E1 partial-info badge, E2 paste control, E3 job card / list row, E4 paste API endpoint. Copy for empty and error states lives in the Copywriting Contract; rows below reference it.

### Resolved (explicit) — truths

- E4 empty: an empty or whitespace-only paste returns HTTP 400 with the `Paste the job description first` error body, and no description is written.
- E4 error: a paste for a job id that does not exist returns HTTP 404 with `{"error": "Job not found. It may have been removed from the list."}`.
- E4 long-text: a paste over 20000 characters returns HTTP 400 with the too-long error body; stored text is never silently truncated.
- E4 partial: `summary.partial_info` is true only when the description is under 500 characters and was not filled from Reed or pasted.
- E1 populated: the `Partial info` badge renders on a job card or row exactly when `summary.partial_info` is true.
- E1 partial: the badge is absent whenever `summary.partial_info` is false (after a Reed match or a paste).
- E2 empty: `Save description` is disabled while the textarea is empty or whitespace-only.
- E2 loading: while saving, `Save description` is disabled with unchanged text and the textarea is read-only; no spinner.
- E2 error: a failed save shows the error in `var(--bad)` directly under the textarea, and the textarea keeps the person's text.
- E2 long-text: a paste over 20000 characters shows the API too-long error under the textarea, and the text is kept.
- E3 partial: a job with `summary.partial_info` true carries the `Only the alert snippet — paste the description for a full score` con and shows the badge.
- E3 partial (filled): after a Reed match or paste, the partial-info con is absent from `cons`.
- E4 populated (re-score): a successful paste stores the text, re-scores the job, and leaves its status unchanged.

### Resolved (backstop)

- { statement: "E2 overflow: the paste textarea has min height 160px, resizes vertically, and long pasted text scrolls inside it without growing the page", verification: backstop }
- { statement: "E3 populated: on a job card/row the score is the primary focal point, then the title; the badge and paste toggle are never larger or higher-contrast than the score", verification: backstop }
- { statement: "E3 overflow: a description up to 20000 characters does not break card or list layout; text wraps and the full description scrolls only in the detail view", verification: backstop }
- { statement: "E3 long-text: a very long job title or pros/cons line wraps within the card without horizontal scroll", verification: backstop }

### Dismissed (reason)

| Element | Category | Reason |
|---------|----------|--------|
| E4 | loading | Synchronous local Flask call; no UI in this phase |
| E4 | overflow | An API response has no visual container |
| E1 | empty | Badge simply absent when the flag is false (covered by E1 partial) |
| E1 | loading | Badge arrives with the job data; it makes no request of its own |
| E1 | error | Badge makes no request of its own, so it cannot fail independently |
| E1 | overflow | Fixed short text `Partial info` |
| E1 | long-text | Fixed short text `Partial info` |
| E1 | zero-one-many | At most one badge per job |
| E2 | partial | Single-field form; no partial submission |
| E3 | empty / loading / error | The job list's own states belong to the UI pages phase (UI-01), which designs the list |
| E3 | zero-one-many | Same: owned by the UI pages phase's list design |
