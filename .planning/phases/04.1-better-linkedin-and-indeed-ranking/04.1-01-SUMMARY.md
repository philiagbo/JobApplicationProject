# Phase 04.1 Plan 01: Reed lookup for LinkedIn/Indeed alert jobs Summary

LinkedIn and Indeed alert jobs now get one Reed API lookup (up to 2 searches, strict company+title match, then 1 details request) in the existing details worker; a match gives the job Reed's full plain-text description, "reed" status and a "Description from Reed" pro. No key, no match or a Reed error ends the job "blocked" with no retry. LinkedIn and Indeed are never contacted.

## What was built

- **core.py**: `details_plan` now returns `skipped` (excluded word) first, `ok` (long text), then `lookup` for LinkedIn/Indeed, else `fetch`. Added `REED_TITLE_MIN`, `_COMPANY_NOISE`, `company_key`, `_LEVEL`, `reed_match` (company equality, title ratio >= 0.9, level-word guard, location tie-break), and the derived "Description from Reed" pro in `score`.
- **sources.py**: `_reed_auth` (extracted from `fetch_reed`), `REED_JOB_URL`, `REED_LOOKUP_RESULTS`, `reed_lookup` (only Reed API URLs; job id forced through `int()`; description unescaped then tag-stripped; error text from the exception only).
- **db.py**: `DETAILS_STATUSES` += reed, pasted; `WORKER_STATUSES`; `save_reed_match` (salary/job type only where empty, new-only re-score, never over 'pasted', url untouched); `init_db` re-pends skipped linkedin/indeed rows.
- **watcher.py**: `lookup` branch (no key -> blocked, returns False so no 5 s gap; key -> lookup, True); explicit `except sources.SourceError` logs a warning with no traceback and marks blocked.
- **Tests**: test_details 43 -> 51, test_core 77 -> 79.
