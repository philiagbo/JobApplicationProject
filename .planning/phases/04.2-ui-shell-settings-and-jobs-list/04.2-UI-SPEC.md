# Phase 04.2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope note (read first)

This phase builds the app shell (top nav, routes, full design tokens), the Settings page, and the Jobs **list** view. It is slices 1 and 2 of `.planning/UI-MAP.md`. Swipe view is Phase 4.3 (it reuses `JobCard`, so `JobCard` must not assume a list parent). Dashboard, Profile and Apply queue pages show a placeholder only.

`.planning/phases/04.1-better-linkedin-and-indeed-ranking/04.1-UI-SPEC.md` is binding and is **extended, not re-decided**: its spacing scale, 4-size/2-weight type scale, `PartialInfoBadge` and `PasteDescription` behaviour and strings are used as written. The one extension: 04.1 called `--ok` "accent" inside its own narrow scope; this phase introduces a real brand `--accent` and keeps `--ok` as the success-only colour (04.1's "Description saved" stays `--ok`).

Users: one non-technical person, Windows PC, desktop browser first, must work down to 320px, light and dark (system preference), WCAG 2.1 AA.

## Spacing Scale

Declared values (multiples of 4), identical to 04.1. CSS names `--space-xs` ... `--space-3xl`.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap glyph-to-label, badge inner padding, gap between a pro/con marker and its text |
| sm | 8px | Gap between chips, between buttons in a row, label-to-input, header vertical padding |
| md | 16px | Card padding, gap between cards, input horizontal padding, page padding below 640px, form field gaps |
| lg | 24px | Page padding at 640px and above, gap between card header and pros/cons |
| xl | 32px | Gap between Settings sections, gap between filter bar and list |
| 2xl | 48px | Score column width, empty-state vertical padding |
| 3xl | 64px | Page bottom padding (room for the toast) |

Exceptions (only these):
- The toast's `--shadow-toast` is `0 4px 8px` (offset and blur are multiples of 4 and match `xs`/`sm`); it is the only shadow in the app.
- Interactive controls (buttons, nav links, chips, inputs, select, tag chips and their remove buttons) are `min-height: 44px` with at least 44px hit width; achieved with `min-height`, not a new token (04.1 rule, extended to every control).
- Borders and focus outlines are 1px / 2px (not spacing).
- Layout max-widths: 720px (Jobs, placeholders), 640px (Settings), 480px (toast).
- One layout breakpoint: 640px. Below it page padding is `md`, above it `lg`.

Contrast (AA): text/bg 17.3 and 16.3; text/surface 15.9 and 14.7; muted/surface 5.26 and 6.38; accent text/surface 5.60 and 8.08; on-accent/accent 6.10 and 8.83; ok/surface 4.61 and 9.30; bad/surface 6.00 and 5.86; border-strong/bg 3.41 (light), 4.39 (dark), border-strong/surface 3.13 (light), 3.98 (dark).

Accent reserved for (explicit, nothing else): (1) the `Save settings` button, the only accent-filled button in the app this phase; (2) the active nav link marker (2px underline); (3) selected filter chips (a handful per view, each also carrying a `✓` prefix); (4) the `N new jobs` pill fill; (5) text links that sit outside job cards: the help links (`Get a free key`, `How to make one`) and the `Go to Settings` / `Go to Jobs` links in empty states and placeholders; (6) the focus ring. **Everything repeated per job card is neutral, never accent:** `Add to queue`, `Dismiss job`, `More details`, `Open listing`, `Paste description`, `Save description`, `Discard description`, the score, pros/cons text, badge, toast and section headings. Accent therefore never lands on more than one button, one pill, and the chips on a screen.

Colour is never the only signal: pros carry a `+` marker under a "Pros" heading, cons a `−` marker under "Cons"; selected chips get a `✓` prefix plus `aria-pressed`; statuses carry a text word (`Working`, `Problem`, `Not checked yet`); errors carry text, not just red.

**Deliberate change from 04.1:** 04.1's Color table drew job cards and the paste panel with a 1px `--muted` border. This phase uses the `--surface` fill with a 1px `--border` instead (a quieter edge that stays legible in dark mode), and keeps `--muted` for text and for the `Partial info` badge outline exactly as 04.1 specifies (muted text, 1px `--muted` outline, transparent fill). 04.1's `--ok` and `--bad` roles for "Description saved" and paste errors are unchanged.

Dark mode is the same layout with the dark column; no elevation shadows. One shadow token is allowed, for the toast only: `--shadow-toast: 0 4px 8px rgb(0 0 0 / 0.2)`.

Radii: exactly two. `--radius-sm: 4px` (buttons, inputs, chips, tags, badge, pill) and `--radius-md: 8px` (cards, panels, toast, banners). No fully rounded pills, no larger radii.

## Interaction Contract

### Shell
1. Navigation uses real links; browser back/forward work; a refresh on any sub-route loads (Flask already falls back to `index.html`).
2. On route change, focus moves to the new page's `<h1>` (`tabIndex={-1}`) and the tab title updates.
3. One `GET /api/jobs?status=new` poll (30 s) lives at the app level so the nav badge and tab title work on every route; the Jobs page consumes it. `usePoll` also refreshes immediately when the tab becomes visible again.
4. **Tab title unread count** = jobs that arrived since the person last saw the list (the pill count, below), not the total. First load counts as seen. Count clears when the pill is clicked.
5. Initial API check: keep the existing `/api/health`-style failure idea, but the user-facing wording is the "Is the app still running?" pattern above (the stub's `API not reachable. Is Flask running?` is developer language and is replaced).

### Jobs list
1. **Order:** score descending, ties newest first (server order). Rendering re-sorts by score; scores changing after a paste or a settings save move the job on the next render. No full reload.
2. **Filters (client-side, instant):** chips come from `career_fields` (`GET /api/settings`). A chip matches when the job title contains the chip text, case-insensitive. No chip selected = all jobs (`All jobs` chip pressed). Several chips = OR. Search matches title or company, case-insensitive substring. Chips and search combine with AND. Filters persist for the visit only (component state). If `career_fields` is empty the chip row is hidden (search stays).
3. **Pagination:** render the first 50 filtered jobs; `Show 50 more jobs` appends 50. Reset to 50 when filters change.
4. **Card (collapsed):** score (Display 28/600, first read) + title (Heading 20/600) + meta line (`{company} · {location} · {salary}`, Label size at weight 400 in `--muted`, parts omitted when missing) + `via {Source}` + `Partial info` badge when `summary.partial_info`. Below: Pros then Cons, **at most 3 of each**, each prefixed by marker and under its heading. Then the actions row: `More details`, `Open listing`, then right-aligned `Dismiss job` (Secondary) and `Add to queue` (Strong). No accent on any of them. Hierarchy per 04.1: the score is never out-weighed by the badge or paste control.
5. **Card (expanded, `More details`):** all pros and cons; `What you'd do` and `What they want` as bullet lists; `Job type`, `Remote`, `Experience` as label/value pairs (only those with a value); then `PasteDescription` (collapsed by default, available on every job per 04.1 rule 1). Descriptions render as text, never HTML.
6. **Dismiss / queue (optimistic):** the card collapses out (200 ms, `grid-template-rows: 1fr → 0fr` + opacity; instant under reduced motion) and the request fires. Success: Undo toast. Failure (404/409/network): card returns in place with the inline error, no toast.
7. **Undo toast:** exactly one at a time; a new action replaces the previous toast (the earlier action becomes final). Auto-dismisses after 5 s; the timer pauses while the toast is hovered or contains focus. `Undo` calls `/api/jobs/<id>/undo`; success: the job reappears at its score position (not at the top) and focus moves to its `More details` button. The toast does not steal focus when it appears (`role="status"`, `aria-live="polite"`, not `alert`).
8. **Focus after an action:** focus moves to the next card's `More details` button (previous card if it was last; the list `<h1>` if the list is now empty).
9. **New-jobs pill:** a poll that returns ids the person has not seen does not insert them. A sticky `{n} new jobs` accent button appears at the top of the list (`top: var(--space-sm)`); `role="status"` wrapper announces it. Clicking merges them by score, scrolls to top (smooth, instant under reduced motion), focuses the `<h1>`, clears the tab-title count. Jobs that disappear (dismissed elsewhere) are removed immediately. Own dismiss/queue/undo never count as new.
10. **Paste description:** exactly the 04.1 contract (states, disabled rule, error under the textarea, success text in `--ok`, badge disappears, card updates in place from the response, status unchanged).
11. **Focal point (Jobs page):** the score and title of the top-ranked card. The page has no accent-filled button other than the new-jobs pill, so nothing competes; the only accent elements are the selected chips and, when present, the pill.
12. **Loading:** `Loading jobs…` text with `role="status"` and `aria-busy` on the list region; no skeletons. Shown only while there is no data yet; later polls update silently.

### Settings
1. Loads `GET /api/settings`, `GET /api/gmail`, `GET /api/watcher` independently, each with its own loading/error state (one failing does not blank the page).
2. **Form model:** the main form (career fields, words to avoid, min salary, location, Reed key, two intervals) is saved with one `PUT /api/settings` via `Save settings`. The button is disabled until something changed (dirty) or while any field is invalid or saving. Success resets the form to the response and shows the success line (stays until the next edit). Do not send Adzuna keys (see Open items).
3. **TagInput:** type + `Enter` (or comma, or the `Add career field` / `Add word` button) adds a tag; whitespace trimmed, empty ignored, case-insensitive duplicates ignored silently. Each tag is a chip with a remove button. Backspace in an empty input does not remove a tag. After add, focus stays in the input; after remove, focus moves to the input.
4. **Reed key field:** shows the masked string; if the person types, the new value replaces it; clearing it and saving removes the key. The server ignores an unchanged masked echo, so the field is always sent.
5. **Gmail:** independent of `Save settings` (own endpoint). Not connected → form + `Connect Gmail`. Connected → address + `Disconnect Gmail` (inline two-step confirm, copy above). The App Password field is cleared after any attempt that succeeded and kept after failure.
6. **Job sources panel:** polls `GET /api/watcher` every 5 s while the tab is visible (every poll is cheap, in-memory). A row per source (Reed, Remotive, Gmail alerts) with name (Label 14/600), status word + glyph, relative time and any error text (`--bad` only for a failed source's error string).
7. **Check now:** `POST /api/fetch`. The request can run for minutes, so the button is disabled and reads `Checking…` while the request is in flight **or** `watcher.fetching` is true (covers a background fetch started elsewhere). Result line in `role="status"`; errors in `role="alert"`. On success, the watcher panel refreshes immediately and the jobs poll refreshes. Disabled with the hint while the form is dirty.
8. After `Save settings`, the jobs poll refreshes (the API re-scores new jobs).
9. **Focal point (Settings page):** the `Career fields` input in the first section (it is what unlocks everything else on first run) and, once edited, the accent `Save settings` button, the only accent-filled control on the page. `Connect Gmail` is Strong and `Check now` is Secondary so neither competes with it.

### Accessibility (WCAG 2.1 AA)
- One `<h1>` per page, `h2` per Settings section; landmarks `header`, `nav`, `main`; skip link; `aria-current="page"` on the active link.
- Every control has a visible label or text; icon-like glyphs are `aria-hidden`. Action buttons carry job context: `aria-label="Dismiss job: {title} at {company}"`, `"Add to queue: {title} at {company}"`, `"More details: {title}"` (use `aria-expanded` and `aria-controls`; every label starts with the visible text, WCAG 2.5.3).
- Inputs: visible `<label for>`; hints and errors linked by `aria-describedby`; errors that appear after user action use `role="alert"`; saved/finished messages use `role="status"`.
- Visible `:focus-visible` ring on everything; never `outline: none` without replacement; tab order follows visual order.
- Chips are `<button aria-pressed>` in a `role="group"` labelled `Career fields`; filter result count is in an `aria-live="polite"` line.
- Target size 44px for every control; no reliance on hover (the toast timer pausing is an enhancement, the Undo button is always a real button).
- Honour `prefers-reduced-motion` (transitions off), `prefers-color-scheme`, and browser zoom to 200% without horizontal scroll at 320px CSS width.
- Verify at 320 / 768 / 1024 / 1440 px, light and dark, keyboard-only (UI-MAP verification list).

## Open items for the planner and orchestrator

1. **Adzuna keys cannot be built.** The scope and UI-MAP list `adzuna_app_id` / `adzuna_app_key`, but `api/db.py` `DEFAULTS` has no such keys and `PUT /api/settings` returns 400 `Unknown setting: ...`. `api/watcher.py` sources are only `reed`, `remotive`, `gmail`. This spec therefore has no Adzuna fields. If Adzuna is wanted, it needs a backend phase first.
2. `react-router-dom` and `motion` are not in `ui/package.json`. This spec needs neither (pushState routing recommended, CSS collapse). 4.3 will need `motion`.
3. `GET /api/watcher` source entries also carry `new` (count from last poll), not listed in UI-MAP; this spec uses it, optionally.
4. Tab-title "unread" is defined as the pill count (arrivals not yet seen), distinct from the nav badge (total in the `new` list). Confirm this is the intent of PLAN.md's "tab title shows the unread count".
5. 44px minimum on every control (including tag chips and filter chips) is deliberate for a non-technical user and touch; it makes chip rows tall. Relax to 32px for chips only if it looks heavy in review.
