<objective>
Make the watcher visible and responsive through the API: saving keys or career fields triggers an immediate poll, `GET /api/watcher` shows each source's last poll and error, and the manual `POST /api/fetch` contract (409 busy, per-source errors, 502 only when all fail, silent skip without a key) is locked by integration tests.

Purpose: Success criterion 3 (a failing source is visible and the others still deliver) and D-10/D-14 need an API surface; the later UI reads these endpoints.
Output: `WAKE_KEYS`, the wake in `settings_put` and the `watcher_status` route in `api/app.py`; new tests in `api/test_api.py`.
</objective>
